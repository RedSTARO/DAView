# DAView UI / UX 审计（使用者视角）

- 基线：`master` @ `a5d913a`。
- 方法：按实际使用顺序（首次配置 → 建库 → 找片 → 详情 → 播放 → 设置与维护）逐页走查界面代码（`composeApp` 的 `src/app`、`androidMain`、`desktopMain`）以及界面直接依赖的 `core` 逻辑。**未构建、未运行**。
- 标记：
  - 〔代码推导〕结论依赖运行时行为，由代码与 Compose / media3 框架语义推出，未实机复现。
  - 〔取决于意图〕是否算问题取决于产品取舍，这里只陈述行为，以及它与常见做法或本应用其他部分的差异。
  - 〔旧表已修复：编号〕已删除的 `docs/UI-UX-BACKLOG.md` 把该编号标为已修复，按当前代码不成立或只部分成立。
- 不做严重度排序。每条写：条件 → 现象 → 位置。

## A. 首次使用与建库

**A1 「创建并扫描」不会扫描**〔两端〕
- 条件：设置 → 添加媒体库… → 选目录 → 点「创建并扫描」。
- 现象：只写入库定义，提示「媒体库已创建」，不启动扫描。新库显示 0 项，首页多出一张 0 项的库卡片，媒体库页的空态让人「在设置里对它执行一次扫描」。要看到内容，还得在库卡片上找到刷新图标，再选「扫描文件并刮削新条目」。
- 位置：`ui/SettingsScreen.kt:1056-1065`（按钮文案）；`data/AppState.kt:730-735`（只调 `createLibrary`）；`core/api/MediaFacade.kt:115-131`（只 upsert）。全仓库 `startScan` 的调用点只有库卡片菜单那三项（`ui/SettingsScreen.kt:171, 184, 188`）。

**A2 配置顺序与引导**〔两端〕
- 条件：全新安装，还没填 WebDAV。
- 现象：首页空态只写「在设置里选择 WebDAV 上的目录作为…库，然后扫描」，没说要先填 WebDAV 连接。设置页第一块是「媒体库 / 添加媒体库…」，WebDAV 表单排在它下面。先点「添加媒体库…」的话，目录选择器请求失败，对话框里只显示异常原文。没有首次使用向导。
- 位置：`ui/HomeScreen.kt:63-70`；`ui/SettingsScreen.kt:104-126, 987-1001, 1019`。

**A3 WebDAV 没有「测试连接」**〔两端〕
- 条件：填写或修改 WebDAV 地址、账号、密码后点「保存存储设置」。
- 现象：地址不通、密码填错也一样只提示「设置已保存」。连接错误要等到打开目录选择器或开始扫描时，才在别处以报错出现。
- 位置：`ui/SettingsScreen.kt:341-346, 388`；`data/AppState.kt:724-728`。

**A4 媒体库建好后不能修改**〔两端〕
- 条件：建库时名称或类型选错，或者想调整刮削源顺序。
- 现象：库卡片上只能扫描和删除，名称、类型、路径、刮削源顺序都没有编辑入口；卡片上的「刮削顺序: …」只能看。`MediaFacade.updateLibrary` 存在，但界面没有调用点；README 写的「每个媒体库可自定义顺序」在界面上做不到。唯一的办法是删库重建，观看进度和收藏会随库一起清掉。
- 位置：`ui/SettingsScreen.kt:143-162`；`core/api/MediaFacade.kt:134-138`。

**A5 目录选择对话框**〔两端〕
- 条件：WebDAV 下子目录较多。
- 现象：
  - 路径行、目录列表、「媒体库名称」、类型按钮都在同一个滚动区域里。目录一多，名称和类型就落到列表末尾，要滚过全部目录才看得到，路径行也跟着滚出视野。
  - 选中的目录就是当前进入的那一层，没有「选择此目录」这个动作；列表只显示目录，看不出里面有没有视频。
  - 每进入一层，名称框都被重置成该目录名，已经手填的名称会被覆盖。
  - 类型固定默认「电影」，不参考目录名。四个类型按钮放在不换行的 `Row` 里，对话框较窄时可能被截断〔代码推导〕。
  - 「上一级」用的是返回箭头图标。
- 位置：`ui/SettingsScreen.kt:976-1068`（名称覆盖 `:994`，滚动容器 `:1009`，上一级 `:1011-1016`，类型行 `:1047-1053`）。

**A6 通知权限在首屏之前索取**〔Android〕
- 条件：Android 13 及以上，首次启动。
- 现象：`setContent` 之前就弹出系统通知权限框，这时背后只有加载底色，也没说明用途（用途是扫描和下载的前台服务通知）。
- 位置：`android/MainActivity.kt:25, 31, 41-49`。

**A7 冷启动先闪一次「还没有媒体库」**〔两端〕〔代码推导〕
- 条件：已经有媒体库，冷启动。
- 现象：`ready` 在库列表读回之前就变成真，首页用空的 `libraries` 渲染至少一帧，先出现「还没有媒体库」空态，再切到正常首页。
- 位置：`data/AppState.kt:287-298, 315-319`；`ui/HomeScreen.kt:63`。

**A8 空态按钮与 tab 切换是两种导航**〔两端〕
- 条件：首页空态点「前往设置」；或者还没有库时点底栏「媒体库」。
- 现象：「前往设置」用压栈方式进入设置，会出现返回箭头；点底栏或侧栏的「设置」是切换 tab，没有返回箭头。同一个页面有两种状态。没有库时点底栏「媒体库」会直接跳到「设置」tab，底栏选中项从「媒体库」变成「设置」，没有任何说明。
- 位置：`ui/HomeScreen.kt:68`；`app/App.kt:420-423`。

## B. 全局框架与导航

**B1 顶栏只有一个返回箭头**〔两端〕
- 现象：除播放页外，每页顶部固定一条 56dp 的栏，里面只有返回箭头，不显示页面标题。首页、搜索、设置、以 tab 进入的媒体库这些根页面上，它是一条空带。首页大图和详情页头图都从这条空带下方开始，不延伸到窗口顶端。
- 位置：`app/App.kt:269-288`。

**B2 宽窗口下所有内容限宽 1180dp**〔桌面 / 平板〕
- 条件：内容区宽度超过 1180dp，例如 1920 宽屏、100% 缩放。
- 现象：限宽作用于所有页面，不只是正文。首页大图、横向片架、媒体库海报网格、搜索网格都被关在居中的 1180dp 里，两侧空着；片架在这 1180dp 里横向滚动。设置页表单同样铺满 1180dp。
- 位置：`app/App.kt:192-199`。

**B3 侧栏顺序**〔桌面 / 宽屏〕
- 现象：顺序是首页 → 搜索 → 设置 → 各媒体库，「设置」夹在全局入口和库列表之间。
- 位置：`app/App.kt:326-372`。

**B4 返回后页面状态不保留**〔两端〕〔旧表已修复：UX-18〕
- 条件：媒体库网格滚到较深处（或已经触底加载过第二页）→ 进详情 → 返回。搜索页、详情页同理。
- 现象：
  - （确定）返回会触发 `onEnter` → `loadLibrary`：网格先被加载占位替换，然后只重新载入第一页（200 条），之前加载的后续页丢失。
  - 〔代码推导〕页面切换用的是 `AnimatedContent`，离开的页面整个移出组合；应用里没有 `SaveableStateHolder`，所以 `rememberLazyGridState()` 和 `rememberSaveable` 的状态会一起丢掉，返回后网格回到顶部。搜索结果网格、详情页的滚动位置也一样。
- 位置：`app/App.kt:231-257`；`ui/LibraryScreen.kt:74-77, 184-192`；`data/AppState.kt:264-276, 388-409`。

**B5 返回详情页时季选择被重置**〔两端〕
- 条件：剧集详情页选中第 3 季 → 播其中一集 → 返回（外部播放结束、重新刮削之后同样如此）。
- 现象：`loadDetail` 每次都把选中季重设为第一个季，所以回来看到的是第一季的列表。和 B4 叠在一起：看完 S03E05 回来，停在第一季列表的顶部。
- 位置：`data/AppState.kt:509-512`。

**B6 详情页「读取失败 / 重试」走不到**〔两端〕
- 条件：打开详情时读取失败（条目已被删除或合并、数据库异常等）。
- 现象：`detailError` 在全仓库只被赋值为 `null`。失败时只弹一条 snackbar，页面留白（`detailItem` 已清空，`detailLoading` 为假）。重试按钮用的 `detailItem?.id` 这时也是空的，就算显示出来也点不动。
- 位置：`data/AppState.kt:489-516`（`:491`）；`ui/DetailScreen.kt:94-104`。

**B7 桌面快捷键**〔桌面〕
- 现象：
  - Backspace 返回写在窗口级 `onPreviewKeyEvent` 里，先于输入框处理，只豁免「搜索」「设置」两页。从首页「媒体库」卡片进入的媒体库是压栈进入的（栈深大于 1），在它的库内搜索框里按退格，页面会退回首页，而不是删掉一个字。详情页对话框里的同类情况见 B15。
  - `Key.AltLeft` 这个分支匹配的是左 Alt 键本身，不是 Alt+←。Alt+← 和鼠标侧键（后退 / 前进）都没有处理。
  - 非播放页上 Esc 什么也不做：不关闭库内搜索，也不返回。
  - 界面上没有任何快捷键说明。
- 位置：`data/DesktopShortcuts.kt:25-51`；`ui/HomeScreen.kt:90`。

**B8 纯图标按钮没有悬停提示**〔桌面〕
- 现象：全仓库没有 `TooltipArea` / `TooltipBox`。详情页的合并、编辑条目信息、手动指定，播放器的音轨、字幕、全屏、结束，库内搜索，这些按钮都只有图标，文字说明只写在给读屏用的 `contentDescription` 里。「编辑条目信息」（`DriveFileRenameOutline`）和「手动指定刮削条目」（`Edit` / `EditNote`）是并排的两支相近的笔。播放器按钮对应的快捷键（#、j、F11）也只写在 `contentDescription` 里。
- 位置：`ui/DetailScreen.kt:494-532`；`desktop/ui/InternalPlayer.desktop.kt:691-702`。

**B9 没有滚动条**〔桌面〕
- 现象：全仓库没有 `VerticalScrollbar`。媒体库网格（可能有几千条）、首页、设置、详情页都只能用滚轮，看不到当前位置和总长度，也不能拖动定位；没有字母跳转。
- 位置：`ui/LibraryScreen.kt:206-237` 等。

**B10 不记忆窗口位置和最大化状态**〔桌面〕〔旧表已修复：UI-43，目前只有尺寸成立〕
- 现象：只在「浮动」状态下保存宽高。每次启动窗口都居中；关闭前是最大化的，下次启动是浮动窗口。
- 位置：`desktop/Main.kt:49-54, 158-163`。

**B11 主题只有深 / 浅，不跟随系统**〔两端〕
- 现象：设置里只有一个「深色主题」开关，默认深色，没有「跟随系统」。Android 系统切换深浅色时，应用不跟着变。
- 位置：`data/AppState.kt:104, 321-324`；`ui/SettingsScreen.kt:458`。

**B12 批量或有损操作不能撤销**〔两端〕
- 现象：snackbar 不带操作按钮。标记已看 / 未看（包括整季、整剧）、从继续观看中移除、删除本地文件，做完只能手动反向再做一次。其中标记已看 / 未看会顺带把续播位置清零（见 F8），反向操作也找不回来。
- 位置：`app/App.kt:159-163`；`data/AppState.kt:557-561, 589-593, 655-660`。

**B13 横向片架上的纵向滚轮**〔桌面〕〔代码推导〕
- 条件：鼠标停在首页或详情页的横向片架上，转动纵向滚轮。
- 现象：`wheelScrollsHorizontally` 把纵向滚动量转成片架的横向滚动，但没有消费这个事件，外层 `LazyColumn` 仍会收到并纵向滚动，结果片架和整页一起动。
- 位置：`desktop/ui/PlatformChrome.desktop.kt:53-65`。

**B14 tab 切换的转场方向**〔两端〕
- 现象：`switchTo` 不更新 `movingForward`，切 tab 时沿用上一次导航的方向；上一次是返回的话，切 tab 也按「返回」的方向滑。
- 位置：`data/AppState.kt:218-248`；`app/App.kt:238-245`。

**B15 在详情页的对话框里按退格，整个详情页会被关掉**〔桌面〕〔代码推导〕
- 条件：在详情页打开「编辑条目信息」「手动指定刮削条目」或「合并重复条目」，在输入框里按 Backspace。
- 现象：桌面上 material3 `AlertDialog` 渲染在同一个窗口里，窗口级 `onPreviewKeyEvent` 比对话框先收到按键。详情页总是压栈进入的（栈深至少为 2），所以 `back()` 会成立并吃掉这次按键：页面退回上一级，对话框跟着详情页一起消失，已经输入的内容全部丢失。
- 位置：`desktop/Main.kt:81-94`；`data/DesktopShortcuts.kt:29, 48-51`；`ui/DetailScreen.kt:403-411`。

**B16 进程被系统回收后，回来就是首页**〔Android〕
- 条件：应用在后台放得较久或内存紧张，进程被回收，再从最近任务回到 DAView。
- 现象：导航栈、选中的季、搜索词、各页位置都放在用普通 `remember` 创建的 `AppState` 里，没有 `rememberSaveable`、ViewModel 或 SavedState。进程重建后回到首页、全部重新加载，之前停在的详情页或库页位置都没了。旋转屏幕这类配置变化已由 `configChanges` 接管，不会触发重建。
- 位置：`app/App.kt:91`；`data/AppState.kt:98`；`composeApp/src/androidMain/AndroidManifest.xml:24`。

## C. 首页

**C1 大图与「继续观看」第一张是同一条目**〔两端〕
- 现象：大图取「继续观看」第一项（没有就取「接下来」或「最近添加」的第一项），紧接着那一行又以同一条目开头，同屏出现两次。大图没有右键菜单，它下方同一条目的卡片却有。
- 位置：`ui/HomeScreen.kt:54, 77-100, 160-233`。

**C2 大图尺寸与层级**〔两端〕
- 现象：高度由 `heightIn(260..380dp)` 决定，不看视口高度；横屏手机或矮窗口下，大图占去大半屏甚至整屏。大图是分集时，分集名是 `headlineLarge` 主标题，剧名是它上方的一行小号链接。
- 位置：`ui/HomeScreen.kt:167-209`。

**C3 同一行里 2:3 和 16:9 的卡片混排**〔两端〕
- 现象：卡片比例按类型定（分集 16:9，其他 2:3），同一行宽度相同、高度不同，底部对齐：
  - 「继续观看」（卡宽 232dp）：电影卡约 348dp 高，分集卡约 130dp 高。
  - 「最近添加」同时有分集（每部剧取最新一集）和电影，152dp 宽下一样混排。
  - 「收藏」里如果收藏了分集也会混排；搜索结果同理（见 E2）。
- 位置：`ui/Components.kt:229`；`ui/HomeScreen.kt:92-119`；`core/db/Repository.kt:613-639`。

**C4 「XX · 未观看」内容固定不变**〔两端〕
- 现象：按排序名取前 24 条没看过的电影或剧。只要观看状态不变，永远是同一批，通常就是字母或拼音最靠前的那些。
- 位置：`core/db/Repository.kt:641-658`。

**C5 各行没有「查看全部」**〔两端〕
- 现象：继续观看 20 条、接下来 20 条、最近添加 24 条、收藏 24 条，超出的部分在首页没有入口；`MediaRow` 的 `trailing` 参数从来没被用上。收藏只能到各个库页用「收藏」筛选一个个库地看；跨库的全部收藏、全部「最近添加」没有对应的页面。
- 位置：`data/AppState.kt:358-365`；`ui/HomeScreen.kt:92-119`；`ui/Components.kt:406-442`。

**C6 每次回到首页，「未观看」行都先消失再出现**〔两端〕
- 现象：`refreshHome` 先写入一份不含 `unwatched` 的 `HomeData`，再把各库的行补上。回到首页、标记已看、播放结束都会触发这一过程，页面下半部分先塌下去再撑回来。
- 位置：`data/AppState.kt:373-385`。

**C7 扫描进度的位置**〔两端〕
- 现象：「正在扫描」排在首页所有行之后，在最底部；顶部和导航栏都没有后台任务的指示。扫描还在排队或读取目录（总数为 0）时，确定型进度条停在 0%。
- 位置：`ui/HomeScreen.kt:132-156`；`ui/SettingsScreen.kt:223-242`。

**C8 区块不可配置，没有下拉刷新**〔两端〕
- 现象：区块顺序写死，也不能隐藏。Android 首页没有下拉刷新；桌面按 F5 可以刷新，但界面上找不到这个入口。
- 位置：`ui/HomeScreen.kt:73-157`；`data/DesktopShortcuts.kt:35-38`。

**C9 剧集卡片不显示未看集数**〔两端〕
- 现象：剧集卡的副标题是「年份 · N 季」，卡片上没有剩余未看的集数，只有全部看完的剧才有一个对勾。追到哪一集要点进详情才知道。
- 位置：`ui/Components.kt:297-312, 398-403`。

**C10 库入口重复**〔宽屏〕
- 现象：宽屏下侧栏已经列出全部媒体库，首页仍然有一行「媒体库」卡片。
- 位置：`ui/HomeScreen.kt:90, 235-276`；`app/App.kt:351-372`。

## D. 媒体库页

**D1 排序、筛选、库内搜索时整个网格先消失再出现**〔两端〕
- 现象：每次重新加载都走 `!loaded || state.libraryLoading -> LoadingPane()` 这个分支，网格被占位替换（150ms 后出现转圈），然后重建。代码注释说「重排时条目保持不动」，实际分支不是这样。

## I. Android 内置播放器

**I1 自动连播换集之后，播放器不换片**〔Android〕〔代码推导〕〔旧表已修复：UX-27〕
- 条件：开着「播完自动播下一集」，一集播完。
- 现象：`ExoPlayer` 以及音轨 / 字幕选择都是用不带 key 的 `remember` 创建的。`playNextIfAny` 只替换了 `info`，播放页没有离开组合，所以播放器不会载入下一集：画面停在上一集的结尾，顶部标题已经变成下一集。之后每 5 秒一次的进度上报，会把上一集的结束位置写进下一集的会话；这个位置如果达到下一集时长的 90%，下一集就被标成已看、续播点清零，否则下一集会得到一个错误的续播点。桌面端把对应的状态全部按 `info.sessionId` 做了 key（`desktop/ui/InternalPlayer.desktop.kt:109-132`），Android 端没有。
- 位置：`android/ui/InternalPlayer.android.kt:91-96, 120-184, 275-282`；`ui/PlayerScreen.kt:48-68`；`data/PlaybackController.kt:240-257`；`core/db/Repository.kt:836-837`。
