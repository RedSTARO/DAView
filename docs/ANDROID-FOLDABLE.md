# Android 折叠屏适配与验收

以 Google [Tier 3 — Adaptive ready](https://developer.android.com/docs/quality-guidelines/adaptive-app-quality/tier-3) 为目标：应用使用可用窗口，折叠、旋转和分屏时保留关键状态，并支持 Android 的标准输入。参照 [Fold-aware UI](https://developer.android.com/develop/ui/compose/layouts/adaptive/foldables/make-your-app-fold-aware) 使用 Jetpack WindowManager 的窗口内铰链信息，不按设备型号猜测姿态。这是开发验收，不是完整 L3 签收或 Google Play 认证。

## 布局取舍

- **浏览与设置**：未选中影片时不留空白详情栏。选中后，只有列表与详情各自扣除导航和系统边距仍有足够空间才双栏；小屏、短分屏和大字体下优先单栏。书本姿态绕开分隔，桌面姿态通常在一个可用面板浏览；软键盘遮住下半屏时可以改用上半屏。短窗口里的搜索结果优先显示标题，不让一张海报挤掉首屏操作。设置在宽面板并排显示分类和表单，窄窗的标题、标签和表单一起滚动；缩放或打开键盘不重建编辑区。退出未保存设置时确认；未保存的密码和密钥不写入界面状态持久化。
- **详情**：电影保持单列。没有浏览伴栏、内容区在默认字体下至少约 880×500 dp，且有实质的剧集／季度或相关影片可导航时，才把简介与内容分开；字号放大后提高要求。选季和阅读锚点按导航条目保存；窄窗不必容纳原窗口的所有可见条目，但不会跳回页首或第一季。选季加载、失败重试与空列表分别显示。
- **播放**：桌面半开时，实际视频宽高比、切口与系统栏扣除后，上半能清楚看视频、下半能放进度条和控制时才采用上下布局；否则在一个连续面板播放。能放下完整控件的分屏依然使用完整控件，极窄窗口优先保证返回、播放／暂停。排版变化不重建应用持有的 ExoPlayer 或渲染视图；Android 仍可管理底层缓冲区。可见但失去焦点时继续播放，真正不可见才暂停。支持视频手动 PiP（包括暂停状态）；Android 12+ 的自动 PiP 不在分屏中抢走播放窗口。

## 系统栏与折叠过渡

- **浏览和系统栏**：状态栏继续显示。首页和详情的封面都在卡片内，不绘制到状态栏或铰链。返回、刷新按钮、滚动区域和弹层留在系统安全区；导航只延伸背景。Android 独立全屏播放恢复隐藏系统栏，退出播放恢复显示；分屏与 PiP 不主动隐藏系统栏。
- **折叠过渡**：保持同一页面与播放会话。姿态变化伴随实际排版变化时，先布置新的安全面板，再用 M3 的 `slow effects` 弹簧淡入新内容，透明度不回弹。即使没有可区分的铰链上报，Android 全屏窗口宽度明显变化（DAView 的判定：至少 144 dp 且相对较窄的一边至少 25%）并重新排版，也可触发这一过渡。仅尺寸触发的兜底不会推断铰链位置或强行做双栏。退出到后台数秒后回来、首次打开、普通旋转、小幅缩放、分屏、PiP 和键盘变化不单独触发动效；系统动画关闭时直接显示最终布局。
- **播放连续性**：视频和字幕层不跟随 Compose 淡入，也不借机重建播放器或渲染视图。只淡入安全区域中的控件；原生控件自动隐藏时也保留一个短暂淡出的细边提示。

## 分项验收（第二轮）

每项分别在候选版本上验收，最后用同一交付 APK 重跑。**ADB 窗口**指 Android 模拟器的真实旋转、尺寸和任务模式；**注入**指真实 App 在 Android 仪器测试内收到逻辑尺寸或 `AppFold` 几何，不等同于 OEM 铰链或外屏。下表的“分屏”单独进行了 Android 系统级验证，不是仅设置模拟标志。

| 任务 | 小屏 | 展开大屏（竖／横） | 半开（书本／桌面） | Android 系统分屏 |
| --- | --- | --- | --- | --- |
| 浏览与设置 | ADB 360×800 dp：单列，点入和返回后搜索词仍在。 | ADB 880×1100／1100×880 dp：先全宽搜索，选中才双栏；返回不重置来源页。通过 ADB 键盘事件输入的设置草稿在宽窄转换中保留，继续编辑和确认舍弃均验证。 | **注入**两种铰链：导航、媒体卡片、返回和设置编辑器避开铰链；跨布局返回命中原媒体库末尾条目。 | ADB 在实际分屏中搜索、进入详情、返回，保留原搜索词。 |
| 详情与选季 | ADB 从 360×800 旋转到 800×360：仍在第二季的原阅读位置附近，打开分集再返回仍见该集。 | ADB 竖／横切换保留第二季和领先条目；另用逻辑 1080×720 dp 验证电影不拆栏、有内容的独立剧集拆栏、收窄后合回。 | **注入**两种铰链：第二季后段阅读位置与控件保留，不强制内部再分栏。 | ADB 交换上下任务，第二季阅读锚点和分集回退保留。 |
| 内置播放 | ADB 小屏旋转不中断同一媒体会话，进度约 1.58→4.60 秒。 | ADB 大屏竖／横切换均保持同一媒体会话、系统任务和可见画面。 | **注入**两种铰链：书本姿态画面与控件在同一安全侧；合适的桌面姿态画面在上，控件和进度条在下。七种逻辑窗口内保持同一 ExoPlayer 和渲染视图，极短窗口可暂停、继续和退出。 | ADB 焦点切至系统设置后，同一媒体会话保持 `PLAYING`，进度 4.02→7.13 秒；退出播放器回到同一详情。 |

自动化基本窗口矩阵使用的**可用**尺寸：336×700、680×940、960×624、984×708（竖铰链）、696×800（横铰链）、384×508 dp（分屏形状）；另有 232×192 dp 极小播放窗口。第二轮结构化矩阵 **15/15**；Android 全量 **48 通过、1 跳过**；桌面 **187 通过、1 跳过**；未签名 Release 构建通过，Lint **0 错误**。播放套件还验证了音频焦点、真正进入后台、播放中和暂停状态下的实际 PiP。

### 沉浸与动效修复回归

- **实际 App 录屏**：在 Android API 36 的普通手机模拟器固定旋转与密度，通过 ADB 把正在显示首页的 Android 窗口从 400×800 dp 切到 840×880 dp，再切回来。两方向的进程和任务不变。逐帧对比旧版、修复版和系统动画倍率为 0 的修复版，可区分 Android 自身的换尺寸过渡和应用内容的淡入。倍率为 0 时没有应用淡入；录屏不是实体铰链或 OEM 外屏切换。
- **系统栏（上一轮沉浸版）**：用小屏、大屏竖屏和横屏的实际截图及系统 Insets 记录确认状态栏仍显示、首页和详情封面当时可绘到状态栏后面、刷新与返回仍可点。首页往下滚后状态栏处没有残留封面。独立全屏播放隐藏状态／导航栏，退出恢复。
- **系统窗口回归**：用同一个修复版 APK 重跑浏览、详情、播放各自的小屏、大屏竖屏、大屏横屏和 Android 系统分屏，**12/12**。分屏将焦点切给系统设置后，同一媒体会话仍在播放（进度约 3.45 → 6.45 秒）。
- **自动回归**：布局与连续性矩阵 **15/15**，其中书本／桌面半开使用注入几何；Android 仪器测试 **54 通过、1 跳过**（未装可选字幕样本），其中 6 项像素测试验证到达帧、最终安全位置、减弱动画与装饰层随滚动；播放器另测了同一 ExoPlayer、渲染视图及播放进度。桌面 **187 通过、1 跳过**，未签名 Release／R8 与 Lint（0 错误）通过。

## 验收边界

- 旧候选曾用 Xiaomi 18 Fold（API 37）验证 OEM 半开、旋转和展开；这不是当前修复版的真机证据。当前 APK 未安装到小米真机，正式包及数据未被覆盖。此前的 Pixel AVD 能切换系统姿态编号，但所用镜像未向 DAView 稳定交付可用的铰链布局，也没有切出可读的外屏；没有把编号变化记为通过。
- 小米真机内外屏接续、Google 建议的 1:1 与 4:3 两种原生折叠设备配置、更多桌面化自由窗口组合、实体键鼠／触控板和触控笔，仍需要专项复验。ADB 的键盘和鼠标事件仅验证实际窗口的基础事件路径。触控笔手写依赖 Android、兼容触控笔和 IME；应用未将密码输入作为手写目标。相机预览、录音和 MediaProjection 不适用。

## 复现

使用专用模拟器或明确用于测试的 `.debug` 实例。构建独立包不会覆盖正式包；测试素材只在 instrumentation APK 内。首次运行仅为该独立包写入离线媒体库，拒绝给已配置远端存储、同步或已有不相关数据的实例注入。测试前在模拟器处理 Android 的首次沉浸模式提示（“Got it”），否则系统提示会遮挡播放器的无障碍树。

```powershell
.\gradlew.bat :composeApp:assembleDebug :composeApp:assembleDebugAndroidTest :composeApp:desktopTest -PdaviewSideBySide=true
.\scripts\verify-foldable-matrix.ps1 -Serial SERIAL -ConfirmDisposableTarget
adb -s SERIAL shell am instrument -w -e class 'com.daview.app.FoldArrivalOnDeviceTest,com.daview.app.DetailEpisodesOnDeviceTest' com.daview.app.debug.test/androidx.test.runner.AndroidJUnitRunner
```

[验收脚本](../scripts/verify-foldable-matrix.ps1) 记录 APK 哈希、逻辑尺寸、安全区、铰链和每项结果；使用 `-Fit native` 可禁止拟合密度，需要至少约 1120×1120 px、160 dpi 的专用 AVD 来跑完矩阵。`-Case book,tabletop` 等可单独验收，`-Case seed` 仅准备内容。手动验证可由「Demo Shows → Demo Fold Series」切至第二季，在后段打开分集；查找「Demo Film 002」播放离线视频。按项目记录用实际系统分屏交换位置，播放时将焦点移到另一 App，并观察同一 MediaSession 的进度。

手动复验动效时，只在专用 AVD 上记录原 `wm size`、`wm density`、旋转与系统动画设置。固定竖屏和 160 dpi、打开有封面的首页，用 `screenrecord` 录制 `wm size 400x800` → `wm size 840x880` → `wm size 400x800`，保持应用在前台，不重启。动画倍率为 1 和 0 各录一次，比较同一最终排版下封面和按钮的中间帧，而不是把 Android 本身的大小切换当成应用动画。复验后还原 AVD 设置。
